# Licensing

| Part | Licence |
|---|---|
| `apps/*`, `services/*`, `packages/*` except SDKs | AGPL-3.0-only ([LICENSE](../../LICENSE)) |
| `packages/sdk-js`, `sdk-node`, `sdk-react-native` | MIT (a LICENSE file in each package) |
| Name and logo | Trademark policy ([TRADEMARK.md](../../TRADEMARK.md)) |
| Contributions | [CLA](../../CLA.md) |

There is no proprietary `ee/` tier: everything is open.

## What this means for you

- **Self-hosting for your own use** (including inside a company): free, no obligations beyond the AGPL
  if you modify the server and let others use it over a network.
- **Modifying the server and running it as a service for others:** you must offer those users the
  source of your modified version (AGPL section 13).
- **Embedding the SDKs in your product:** MIT. Your application is not subject to the AGPL.
- **Offering a hosted service under the Clickroom name:** needs permission; forks must rename
  ([TRADEMARK.md](../../TRADEMARK.md)).

## Why AGPL plus MIT SDKs

AGPL asks hosted forks to publish their changes while the MIT SDKs keep adoption frictionless.
The CLA lets the maintainers keep relicensing options. The trademark covers what a code licence
cannot. The licence protects the code, not observable behaviour. This is not legal advice.
